# FLY-TRANCE

Рабочий настольный прототип: **Magenta RealTime 2 Small + настоящий FlyWire CX512 из LiquidAion**. Музыкальный трансформер служит инструментом, а динамика коннектома вмешивается в его внутренние активации. Приложение сохраняет основу LiquidAion Neural Observatory: анатомический мозг, активность нейронов и компактные панели управления.

## Быстрый запуск на Ubuntu 24.04

Python 3.12+, 32 GB RAM. Для CUDA нужен установленный NVIDIA driver, совместимый с выбранной сборкой PyTorch. CUDA toolkit для обычного запуска не требуется.

```bash
sudo apt install python3-venv libportaudio2 libegl1 libgl1 libxcb-cursor0 libxkbcommon-x11-0
bash scripts/install.sh --cuda
bash scripts/start.sh
```

Для CPU вместо `--cuda` используйте `--cpu`. CPU генерирует корректный звук, но может работать медленнее воспроизведения. Если слышны паузы, выключите `Play through audio device` и сначала запишите WAV. Производительность RTX 3070 Ti здесь ещё не измерена.

1. Нажмите **Load Magenta RT2 Small**. При первом использовании загружаются веса и код выбранного порта с закреплённой ревизии Hugging Face. Интернет нужен для первой загрузки.
2. Оставьте **Style** пустым для первого запуска. Текстовый стиль дополнительно загружает MusicCoCa, который работает на CPU. Это необязательный компонент.
3. Нажмите **Start**. По умолчанию на диск ничего не записывается. Чтобы сохранить сессию, перед Start включите **Save recording** в блоке SESSION / RECORDING: тогда в папке `outputs` создаются стерео WAV 48 kHz, metadata и telemetry.
4. Включайте **Fly**, меняйте силу, слои считывания и вмешательства, инерцию `Leak`. В `Dynamics` доступны рекуррентное усиление и сила входного сигнала.
5. **Stop** завершает сессию и запись, если она включена. Следующий **Start** создаёт новую сессию с указанным seed.

Можно указать уже скачанную папку Small вместо Hugging Face ID:

```bash
bash scripts/start.sh --model /absolute/path/to/magenta-realtime-2-small
```

Локальная папка должна содержать `config.json`, `model.safetensors` и Python-файлы PyTorch-порта. Загрузка использует `trust_remote_code=True`: по умолчанию код закреплён ревизией ниже; локальные файлы выбирает пользователь.

## Переключатель Fly

**ON:** выход CX512 добавляется во внутреннюю активацию выбранного temporal-слоя.

**OFF:** добавка полностью отключена. CX512 продолжает получать активации, обновляться и отображаться. Кэш, кодек, случайный генератор и история музыки сохраняются. При повторном включении используется текущее состояние мозга. Уже сгенерированное аудио в очереди воспроизведения не меняется.

Новый параметр применяется на границе следующего модельного кадра. Один кадр составляет 40 ms музыкального времени; фактическая задержка включает вычисление, кодек и очередь аудио. Это не обещание задержки 40 ms на любой машине. Очередь ограничена одной секундой и отображается на экране.

Изменения `Leak`, рекуррентного усиления, входа и точки считывания могут менять состояние мозга при выключенном Fly. На музыку они начнут влиять только после включения инъекции.

## Подключение

```text
Magenta temporal activation -> 64 features -> CX512 -> projection -> temporal residual activation
```

Считывание и добавка происходят после FFN выбранного блока. Если слой вмешательства расположен раньше слоя считывания, используется предыдущее состояние CX512, то есть появляется задержка на один модельный кадр. Возможны любые из 12 temporal-слоёв Small. Входная и выходная проекции фиксированы seed=42. Случайность проекции не заменяет коннектом: рекуррентные связи берутся из проверяемого оригинального графа.

Выходная проекция не нормализуется заново на каждом кадре, чтобы сохранять изменение амплитуды резервуара. Сила добавки масштабируется RMS активации модели. При большой силе результат может резко изменяться; циклы и устойчивые режимы в этой первой версии не подавляются автоматически.

CX512 работает на CPU; трансформер и встроенный декодер SpectroStream на выбранном CPU/CUDA. Путь вмешательства явно встроен в функциональный temporal step. `torch.compile`, CUDA Graphs и готовые AOTI temporal-графы не включены: они требуют отдельной проверки совместимости с этим путём.

Изменение стиля сохраняет состояние потока, но вычисление нового conditioning пока занимает тот же рабочий поток. Во время первой загрузки MusicCoCa или вычисления стиля воспроизведение может прерываться. Для непрерывной первой сессии задавайте стиль до Start.

## Панель Transformer Activity

Справа от мозга находится панель **Transformer Activity**. Её ширину меняют разделителем. Панель скрывает флажок **Transformer activity** под мозгом или перетаскивание разделителя до края. Пока панель скрыта, активации не собираются и не передаются. Переключение панели, выбор слоя и изменение шкалы не перезапускают генерацию и не сбрасывают CX512, KV-кэш, кодек, RNG или историю музыки.

- Столбики показывают temporal-слои загруженной модели: для Small это 12 слоёв по 1024 координаты. Число слоёв и размерность берутся из модели.
- Все столбики снимка относятся к одному модельному кадру. Точка измерения одинакова в каждом блоке: residual stream после FFN (`x + FFN(x)`), а для блока в bypass — переданный дальше вход блока, до добавок CX512 и ручной. Наблюдение встроено прямо в функциональный путь `FlyCoupling.temporal_step`, поэтому не зависит от forward hooks.
- Клетка показывает среднее группы соседних координат. Для Small группа содержит 16 координат, всего 64 группы. Синий цвет означает отрицательное среднее, красный положительное, тёмный цвет означает значение около нуля. Узкая полоска рядом показывает RMS той же группы. Поэтому активность видна, даже если положительные и отрицательные координаты взаимно гасятся. Группы являются техническим сжатием вектора. Это не нейроны, не ансамбли и не музыкальные признаки.
- Для средних и для RMS используются две отдельные шкалы, каждая общая для всех слоёв. Шкала линейная, её диапазон медленно подстраивается по 99-му перцентилю с постоянной времени 5 s или задаётся вручную в режиме `Fixed`. Столбики не нормализуются по отдельности, поэтому видно реальное нарастание амплитуды с глубиной. Жёлтая метка отмечает клетки за пределами шкалы. У Small несколько групп с очень большими координатами заметны во всех слоях.
- `R` отмечает слой считывания в CX512, `I` отмечает слой вмешательства. При Fly OFF рамка `I` пунктирная. `B` отмечает блок в bypass. Зелёная рамка вокруг клетки означает, что на кадре снимка к ней была применена ручная добавка. Белая пунктирная рамка показывает вашу текущую команду. Подсветка берётся из конфигурации, с которой был посчитан снимок, а не из текущих контролов.
- Щелчок по столбику показывает номер слоя, размерность, RMS, минимум и максимум. При наведении на клетку видны её координаты, среднее и RMS.
- **Base / CX512 / Manual / Result** показывает для выбранного слоя четыре столбца: исходную активацию, фактически полученный вклад CX512, фактическую ручную добавку и итог, переданный следующему блоку. Добавки измеряются как разности в dtype модели. Под картой выводятся их RMS, доля от опорного вектора и опорный RMS ручной добавки. Это локальное измерение, а не сравнение с траекторией без мухи или без ручных вмешательств. При Fly OFF вклад CX512 равен нулю точно. Флажок `×10` усиливает только отображение двух столбцов добавок и меняет их подписи. Числа всегда даются без усиления.
- Снимки обновляются примерно 5 раз в секунду по часам, независимо от скорости модели. Строка состояния панели показывает номер кадра, музыкальное время (кадр × 40 ms) и версию конфигурации Fly. С включённым **Sync with audio** в ней написано, через сколько миллисекунд после начала своего звука показан снимок. Без синхронизации там указано, насколько генерация опережает воспроизведение.

### Sync with audio

Генерация опережает звук на длину очереди воспроизведения: в замерах около 0.3–1 s. Без синхронизации мозг и карта показывают то, что прозвучит позже. Флажок **Sync with audio** под мозгом (включён по умолчанию, выбор запоминается) задерживает мозг, график выбранного нейрона и карту активаций так, чтобы показывалось состояние, звук которого слышен сейчас. Только тогда совпадение «вижу — слышу» можно связывать с конкретным звуком.

Как считается момент:

- Звук токенов модельного кадра начинается с первого сэмпла следующего аудиофрагмента: у кодека задокументирована задержка в один кадр.
- Слышимый сейчас сэмпл — это число сэмплов, отданных аудиоустройству, минус выходная задержка, которую сообщает PortAudio (на этой машине 40 ms).
- Каждое состояние ждёт в ограниченном буфере и показывается, когда до него доходит звук. Если созрело сразу несколько, показывается последнее. При провалах звука показ тоже ждёт. После Stop недозвучавшие состояния отбрасываются.

Точность. Состояния мозга приходят около 10 раз в секунду, снимки слоёв около 5 раз. Оценка задержки устройства берётся у PortAudio и может отличаться от фактической. Отрисовка мозга ограничена 10 кадрами в секунду. Поэтому рассчитывайте примерно на ±0.1 s, а не на совпадение до сэмпла. Без аудиоустройства (Play through audio device выключен) синхронизация невозможна, и показывается момент генерации. Подтверждения ручных вмешательств, время шага и очередь всегда показываются сразу.

Производительность. Кадр для наблюдения выбирается один раз до прохода по слоям, на остальных кадрах дополнительной работы нет. На выбранном кадре сводки по всем слоям считаются на устройстве модели без autograd. На CUDA они копируются в CPU одним асинхронным пакетом и забираются после синхронизации, которая и так нужна для аудио кадра. Отдельных `.item()` нет. Worker не ждёт GUI: в буфере хранится только последний снимок, а более старый неотрисованный снимок заменяется.

## Ручное управление активациями

Это экспериментальный инструмент: необычное звучание не исправляется автоматически.

Как пользоваться. В панели нажмите **Manual control ▸** и включите **Intervene with the mouse**. Пока режим выключен, щелчок по карте только выбирает столбец. В режиме вмешательства:

- Нажатие на клетку выбирает её группу координат: для Small это 16 соседних координат слоя. Подсказка над клеткой показывает реальные индексы координат.
- **Pulse (1 frame)** добавляет вектор ровно на одном модельном кадре. Импульс отправляется при отпускании кнопки. **Hold (while pressed)** добавляет вектор на каждом модельном кадре, пока кнопка нажата.
- Знак задают кнопки `+`/`−`. Правая кнопка мыши берёт противоположный знак. Начальную силу задаёт поле `× RMS`. Перетаскивание вверх или вниз меняет знаковую силу: 100 px = 1.0, предел ±4.
- Удержание снимается при отпускании кнопки, потере фокуса картой или окном, скрытии панели, выключении режима, Clear, Stop или новом Start. Дополнительная защита на стороне генерации: если GUI перестал подтверждать удержание (каждые 150 ms), через 1 s оно снимается с причиной `timeout`. Даже очень короткое нажатие в режиме Hold действует ровно один кадр.
- Галочки **Block output bypass** (по одной на temporal-блок) включают bypass выхода блока.
- **Clear manual interventions** снимает удержание, удаляет ещё не применённые импульсы и возвращает все блоки из bypass. Настройки Fly, CX512, RNG, кодек, кэши и уже созданная музыка не меняются. Clear прекращает новые вмешательства, но не возвращает музыку на траекторию без них.
- Строка с галочкой ✓ и журнал под мозгом показывают подтверждения от потока генерации: что применено и на каком модельном кадре. Однокадровый импульс может не попасть в снимок карты, поэтому его подтверждение приходит отдельно.

Правило добавки. Пусть `ref` — RMS всего вектора слоя непосредственно перед ручной добавкой, то есть после bypass и добавки CX512. Каждая координата выбранной группы получает `signed_strength × ref`, остальные координаты не меняются. Несколько операций на одном слое складываются, итог не нормализуется. Опорный RMS считается до ручной добавки, поэтому удержание не усиливает само себя. Если RMS меньше `1e-3` или не конечен, вместо него берётся `1e-3`. Сила проверяется на конечность и предел ±4. Внутренние активации модели ничем не ограничиваются.

Bypass выхода блока. Блок по-прежнему выполняет все штатные вычисления, и его кэши внимания продвигаются как обычно, но следующий блок получает вход этого блока вместо его выхода. Ускорения нет, и это не удаление блока из модели. Повторное включение не очищает кэши и не перезапускает поток. Контекст, накопленный за время bypass, уже несёт его последствия. На карте для такого блока показан фактически переданный дальше сигнал, а вычисленный и отброшенный выход не показывается.

Порядок операций в каждом temporal-блоке:

1. Сохранить вход блока.
2. Выполнить штатные вычисления блока и обновить его кэши.
3. При bypass взять сохранённый вход вместо вычисленного выхода.
4. Существующее считывание в CX512, если это слой считывания.
5. Добавка CX512, если Fly ON и это слой вмешательства.
6. Ручная добавка.
7. Передать результат следующему блоку.

При выключенных новых функциях путь совпадает с прежним, и токены генерации побитово те же. Fly и ручное управление независимы: Fly OFF не отключает ручное управление, а Clear и выключение режима не трогают Fly.

Потоки. GUI не обращается к тензорам и CUDA. Он пишет желаемое состояние в потокобезопасный почтовый ящик, а поток генерации читает его один раз на границе каждого кадра:

- Сила при перетаскивании объединяется по принципу «последнее значение».
- Импульсы ждут в очереди не длиннее 8; лишние отклоняются с сообщением.
- Отпускание и Clear меняют состояние напрямую, поэтому не теряются за событиями мыши.
- Индексы и значения добавки строятся на устройстве модели. Опорный RMS читается в CPU только для событий журнала и только после синхронизации, которая и так нужна для аудио кадра.

Журнал. События пишутся в `events` файла `*.json` сессии (если запись включена) и показываются в журнале на экране. Типы событий:

- `manual_pulse`;
- `manual_hold_start`;
- `manual_hold_update` — не чаще 4 раз в секунду, только в файле;
- `manual_hold_end` — с причиной: `release`, `focus lost`, `window inactive`, `hidden`, `panel hidden`, `manual mode off`, `clear`, `new session`, `closing`, `timeout`, `stop`;
- `bypass`;
- `manual_clear`.

У каждого события есть `effective_frame` — номер модельного кадра, на котором состояние было фактически применено. `layer` — индекс слоя с нуля, `coordinates` — полуинтервал `[start, stop)` реальных индексов координат. Для операций с силой записываются запрошенная `strength`, опорный `reference_rms` и итоговая добавка `per_coordinate`.

## Отзывчивость интерфейса

Генерация и интерфейс работают в одном процессе. Любой Python-код GUI-потока конкурирует с потоком генерации за GIL, а синхронный рендер 3D-сцены занимает GPU одновременно с CUDA. Поэтому:

- Все перерисовки мозга идут через один планировщик. Новые данные активности рисуются не чаще 10 раз в секунду, вращение и масштаб — не чаще 30 раз в секунду, всегда последнее состояние. Синхронного рендера на каждое событие мыши нет, вращение и масштабирование работают как прежде.
- Наведение курсора на мозг и на карту активаций не вызывает Python-обработчиков. Выбор нейрона выполняется только по клику без перетаскивания. Маркер выбора и геометрия сцены не пересоздаются, обновляются только существующие данные.
- Подсказки на карте появляются после штатной задержки Qt и не пересоздаются, пока курсор остаётся в той же клетке.
- Телеметрия и снимки передаются через буфер «последнее значение». Если GUI отстаёт, старые записи пропускаются, а не копятся.
- Приложение выставляет `__GL_SYNC_TO_VBLANK=0`, если переменная не задана. Иначе драйвер NVIDIA ограничивает обмен буферов перекрытого окна примерно одним кадром в секунду, и каждый рендер блокировал бы GUI на секунду. Возможен тиринг в 3D-виде.
- В строке под мозгом видны время шага модели (среднее, p95, максимум за последние ~5 s), число медленных шагов (> 60 ms) и частота и стоимость 3D-рендера. Те же данные о шаге записываются в телеметрию.

Если запущенная сессия всё равно не успевает за воспроизведением, причина в нехватке запаса по времени шага модели на данной машине, а не только в интерфейсе. См. `docs/VALIDATION.md`.

## Что именно является настоящим

Включены исходные 512 FlyWire root IDs, 16 731 направленная связь и 310 999 суммированных синапсов. Проверяются SHA256 файлов из `provenance.json`. Отображаются исходные зарегистрированные координаты и анатомические сетки LiquidAion; геометрия не генерируется.

Динамика представляет собой вычислительную leaky-tanh rate-модель, а не биофизическую симуляцию. Веса исходного графа положительны; знак синапсов не выводится автоматически из neurotransmitter-аннотаций. Группы DA/ACH/GABA/GLUT/SER в панели являются масками аннотаций, а не доказанными музыкальными функциональными ансамблями. DA в этой панели не означает реализованное дофаминовое обучение.

В этой версии нет подкрепления от аудитории, пластичности синапсов, обучаемых музыкальных специализаций или восстановления полной музыкальной сессии после перезапуска. Задача первой версии: слышимое прямое влияние коннектома и ручное исследование его динамики.

## Запись и диагностика

Галочка **Save recording (WAV, metadata, telemetry)** при каждом запуске окна снята и применяется при следующем Start. Пока она снята, GUI ничего не пишет на диск. Для справки: 13 минут сессии занимают около 150 MB WAV и 73 MB telemetry. Когда галочка включена, для GUI-сессии создаются:

- `*.wav`: музыка; громкость воспроизведения не меняет запись.
- `*.json`: модель, seed, параметры графа и история изменения Fly/стиля с номером модельного кадра.
- `*.telemetry.jsonl`: состояния всех 512 нейронов примерно до 10 раз в секунду, параметры, сила добавки, границы аудио в сэмплах, положение воспроизведения и размер очереди.

Визуализация отражает текущее вычисляемое состояние, поэтому может опережать звук на размер очереди. Временные метки дают привязку к созданным фрагментам; точный акустический эффект вмешательства дополнительно зависит от памяти кодека и модели. Stop отбрасывает остаток очереди воспроизведения, но WAV содержит всё созданное аудио.

WAV записывается по ходу генерации, без накопления всего звука в RAM. История активности тоже пишется на диск. Кэш внимания ограничивается штатным окном модели; полный токеновый префикс не накапливается. Следите за свободным диском при долгих сессиях.

## Без интерфейса

После установки:

```bash
.venv/bin/fly-trance-render --device cuda --seconds 60 --fly --strength 0.15 --output outputs/fly.wav
```

Для сравнения запустите вторую запись без `--fly`, с тем же seed. Такой отдельный эксперимент отличается от интерактивного переключения в одной непрерывной сессии. CLI создаёт WAV точной запрошенной длительности и JSON с временем вычисления.

## Проверки

```bash
.venv/bin/pip install -e '.[test]'
.venv/bin/python -m pytest -q
FLY_MODEL_DIR=/absolute/path/to/small .venv/bin/python -m pytest -q
QT_QPA_PLATFORM=offscreen FLY_MODEL_DIR=/absolute/path/to/small .venv/bin/python tests/gui_smoke.py
FLY_TEST_DEVICE=cuda FLY_MODEL_DIR=/absolute/path/to/small .venv/bin/python -m pytest -q -k activation
QT_QPA_PLATFORM=offscreen FLY_TEST_DEVICE=cuda FLY_MODEL_DIR=/absolute/path/to/small .venv/bin/python tests/gui_activity_smoke.py
FLY_BENCH_DEVICE=cuda FLY_MODEL_DIR=/absolute/path/to/small .venv/bin/python tests/bench_activations.py
```

`gui_activity_smoke.py` проходит через настоящий worker с панелью активаций. В нём выполняются Fly ON/OFF, скрытие и повторный показ панели, ручное удержание с перетаскиванием, импульс, bypass, снятие удержания потерей фокуса и Clear. Затем журнал сессии сверяется с подтверждениями worker'а. С `FLY_TEST_MONITOR=1` он открывает аудиоустройство с громкостью 0. `bench_activations.py` чередует режимы без наблюдения, с наблюдением 5 раз в секунду и на каждом кадре. `gui_interaction_bench.py` запускает видимое окно и подаёт синтетические Qt-события мыши для сценариев покоя, наведения, вращения и ручного перетаскивания.

Обычные тесты не скачивают веса. Опциональный тест с локальной моделью проверяет побитовое совпадение OFF с исходным шагом, непрерывность состояния при переключении, конечность аудио и ограниченность кэша. GUI smoke проходит через настоящий Qt worker и запись WAV с переключением ON/OFF/ON. Результаты выполненных проверок находятся в `docs/VALIDATION.md`.
