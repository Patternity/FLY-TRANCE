# Проверки первой версии

Дата: 2026-10-17. Выполнено в CPU-песочнице, Python 3.12; конкретные версии записаны в `tested-versions.json`.

## Выполнено

- `pytest`: **5 passed**, включая настоящий Magenta RT2 Small с локальными весами; финальный запуск 24.73 s.
- Замена temporal step при Fly OFF побитово совпала с оригиналом для выходной активации и обоих типов KV на одинаковом входе.
- На 56 последовательных кадрах проверены ON/OFF, отсутствие сброса CX512, state кодека, KV и RNG при конфигурации, конечность аудио и ограничение длины KV штатным `temporal_max_past + 1`.
- Проверены оригинальные 512 IDs, 16 731 ребро, 310 999 синапсов и контрольные суммы графа.
- Проверены ограничение очереди воспроизведения и обработка частично доступного аудиоблока callback-ом.
- Настоящее Qt-окно с VTK/FlyWire-анатомией запущено и визуально проверено через headless OpenGL. Сквозной тест GUI загрузил модель, сгенерировал музыку, переключил ON/OFF/ON и сохранил WAV, metadata JSON и 14 снимков активности. Мониторинг звука в этом тесте был выключен.
- CLI записал точно **9600 стереосэмплов при 48 kHz**, то есть 0.2 s аудио. Время собственно генерации 2.80 s в данном коротком запуске, без загрузки весов. Это smoke test, а не оценка установившейся производительности.
- Собран wheel; анатомические данные и граф включены в package data (28 файлов). Проверены компиляция Python и синтаксис shell-скриптов.

## Не проверено

- RTX 3070 Ti: скорость, VRAM, непрерывное прослушивание и многочасовая стабильность.
- Физическое аудиоустройство: PortAudio callback проверен программно, звуковой выход в песочнице не прослушивался.
- Скачивание и исполнение дополнительного MusicCoCa в новой версии приложения. Пустой conditioning проверен. Репозиторий и ревизия дополнительного компонента подтверждены; обработчик использует API исходного порта.
- Все возможные сочетания слоёв, групп нейронов и предельных параметров.
- Установка с нуля на пользовательской Ubuntu. Приведены установщик CPU/CUDA и список системных библиотек; тестовая среда уже имела PyTorch.

## Панель Transformer Activity (2026-10-18)

Машина пользователя: Ubuntu, Python 3.12.3, torch 2.11.0+cu128, NVIDIA GeForce RTX 3070 Ti (bf16), 16 логических CPU. Веса Small уже лежали в кэше Hugging Face и повторно не скачивались (`HF_HUB_OFFLINE=1`).

- `pytest` без весов проверяет механизм на игрушечном функциональном стеке с тем же интерфейсом (`step_fn`, `_kv`, `attend_fn`, `ffn`). Проверено: наблюдение не меняет выходы, KV и состояние CX512; сводки совпадают с независимыми forward hooks на FFN, включая неполную последнюю группу; при Fly OFF добавка равна нулю точно; переключение посреди потока ничего не сбрасывает; частота выбора кадров около 5 Hz при 25, 23 и 50 кадрах в секунду; буфер хранит не больше одного снимка; панель отрисовывается offscreen.
- Настоящая Small, CPU fp32 и CUDA bf16. Три сессии по 40 кадров с seed 42 и Fly ON → OFF: без наблюдения, с наблюдением на каждом кадре, с включением и выключением наблюдения посреди потока. Токены и состояние CX512 совпали побитово, аудио совпало с допуском 1e-6. При каждом переключении сохранились объекты KV-кэша и кодека, состояние RNG, CX512 и номер кадра. Все снимки содержат 12 слоёв × 64 группы для одного кадра, данные конечны. При Fly OFF добавка равна 0, при Fly ON она положительна. Статистики и средние групп совпали с forward hooks на FFN того же кадра.
- Сквозной GUI-тест: CUDA, настоящий Qt worker, аудиоустройство ALSA при громкости 0, около 15 s музыки. Последовательность: Fly ON → OFF, скрытие и показ панели, Fly ON. Получено 66–68 снимков при 4.9–5.0 снимка/s, без пропусков. Пока панель скрыта, снимков нет. Номера кадров телеметрии и снимков не перезапускались. В снимках при Fly OFF добавка нулевая. Медианное опережение генерации относительно воспроизведения 0.26–0.28 s. Регрессионный `gui_smoke.py` на CPU также пройден.
- Накладные расходы на CUDA: `tests/bench_activations.py`, Fly ON (read 10 → inject 8, strength 0.5), без GUI, чередующиеся блоки по 125 кадров, 10 раундов, другое приложение FLY-TRANCE закрыто. Средняя длительность кадра без наблюдения 38–39 ms. Попарная разница при 5 Hz в двух сериях: −0.34 % ± 2.17 % и +3.11 % ± 3.51 % (95 % CI). Это не отличается от шума. Прямой замер кода наблюдения: 0.32 ms CPU на наблюдаемый кадр плюс 0.02 ms на сбор, при 5 Hz это около 0.2 % времени. Обновление и перерисовка панели в GUI-потоке занимает около 1.6 ms на снимок.
- Накладные расходы на CPU (fp32, 4 потока torch, 6 раундов по 50 кадров). Кадр длится около 242 ms, RTF около 6, поэтому снимков около 4.1/s, то есть каждый кадр. Попарная разница +0.03 % ± 1.51 %. Код наблюдения занимает 0.25 ms на кадр.
- `scripts/start.sh` с `QT_QPA_PLATFORM=offscreen` и отдельным `XDG_CONFIG_HOME` запустил окно с панелью. Через 25 s процесс работал без ошибок и был остановлен по таймауту. Кнопки в этом запуске не нажимались; полный путь проверен GUI-тестами.

Не проверено: Windows (в проекте и исходном архиве нет `.bat`), прослушивание звука ушами, многочасовая работа панели, видимый экран (только offscreen-рендер).

## Отзывчивость GUI и ручное управление (2026-10-18)

Та же машина: RTX 3070 Ti, X11 + GNOME с композитингом, HiDPI ×2. Веса не скачивались.

Найденные причины лагов генерации при работе с интерфейсом:

- `BrainView` рендерил сцену синхронно на каждую телеметрию (10/с) и при вращении на каждое событие мыши.
- Picking выполнялся на каждое нажатие левой кнопки, включая начало вращения, а выбор нейрона пересоздавал actor.
- Подсказки карты активаций обновлялись `QToolTip.showText` на каждое движение мыши.
- Телеметрия шла неограниченной очередью Qt-сигналов.
- Перекрытое GL-окно на NVIDIA блокировало каждый рендер примерно на 1 s (ограничение swap). Рендер до показа окна мог зависнуть.
- Эксперимент: модель в отдельном процессе, GUI с теми же нагрузками в другом. Шаг 37.1 / 37.6 / 36.5 ms в покое, при наведении и при вращении, то есть сам 3D-рендер почти не конкурирует за GPU. Внутри одного процесса оставшееся замедление объясняется конкуренцией за GIL: PyTorch отпускает GIL на каждой операции, и любой Python-код GUI-потока задерживает поток генерации.
- Что исправлено, описано в README, раздел «Отзывчивость интерфейса».

Замер `tests/gui_interaction_bench.py`: видимое окно на реальном дисплее, синтетические Qt-события мыши примерно 125/с (курсор ОС не двигается), CUDA, Fly ON, аудиоустройство с громкостью 0, 10 s на сценарий после 2 s переходного периода. «До» — текущее приложение с исходным `brain_view.py` из v0.1.0, «после» — текущий код. Средний шаг модели:

| Сценарий | До | После |
|---|---|---|
| Курсор стоит, панель видна | 39.9–40.0 ms | 40.6–41.3 ms |
| Вращение 3D | 49.8 ms, RTF 1.24, 126 underruns | 44.5 ms, RTF 1.11, 74 underruns |
| Наведение на 3D | 43.3 ms | 43.7 ms |
| Ручное удержание с перетаскиванием | 44.3 ms | 44.3 ms |
| Контроль: те же события в пустую метку | 42.7 ms | 44.0 ms |

Вращение рендерится 30 раз в секунду вместо одного рендера на событие. Наведение и ручное перетаскивание стоят столько же, сколько контрольный сценарий, значит остаток — это Python-код самого стенда в GUI-потоке. Реальное наведение мыши теперь не вызывает Python-обработчиков. Уменьшение `sys.setswitchinterval` до 1 ms не помогло (при вращении стало хуже) и не применено. Даже в покое шаг около 40 ms при бюджете 40 ms, и underruns бывают без всякого взаимодействия. Запас по времени шага на этой машине почти нулевой. Отдельный процесс генерации, по эксперименту выше, дал бы около 37 ms и при активном GUI; он не реализован.

Ограничения замера. Синтетические события — не настоящая мышь, хотя проходят через те же обработчики Qt. Ранняя серия этих замеров отброшена: тестовое окно получало флаг «поверх всех» после создания, Qt пересоздавал нативное окно, и VTK рисовал в уничтоженное окно. Мозг тогда был чёрным, а стоимость рендера заниженной. В приложении флаги окна не меняются. Вывод мозга на экран проверен снимком экрана, в том числе с копией сохранённых настроек окна пользователя.

Ручное управление:

- `pytest` без весов: 27 тестов на функциональном стеке с интерфейсом MRT2. Проверено:
  - при выключенных функциях путь побитово совпадает с копией исходного `temporal_step` v0.1.0;
  - импульс действует ровно один кадр;
  - добавка затрагивает только координаты группы и равна `strength × ref`;
  - удержание действует до отпускания, сила берётся по последнему значению, короткий клик даёт один кадр;
  - сторожевой таймаут срабатывает;
  - Clear отменяет ожидающие импульсы, удержание и bypass, не трогая Fly, CX512, кэши и номер кадра;
  - bypass передаёт вход блока, кэши всех блоков продвигаются, повторное включение ничего не сбрасывает;
  - Fly и ручное управление независимы;
  - пределы и валидация работают, Stop закрывает удержание;
  - журнал совпадает с применёнными операциями;
  - GUI-жесты в Qt (offscreen) работают, включая потерю фокуса, скрытие, правую кнопку, Clear и безопасный режим просмотра.
- Настоящая Small на CUDA и на CPU (весь набор, 30 тестов на CPU):
  - без вмешательств токены и аудио совпадают с исходным шагом v0.1.0;
  - импульс применён только на кадре 5, удержание на кадрах 22–25, после Clear ничего не применено;
  - изменилась только выбранная группа координат;
  - в bypass статистики входа блока 7 побитово равны результату блока 6;
  - длина KV всех слоёв растёт до штатного предела;
  - журнал: pulse@5, bypass@10, bypass@20, hold_start@22, hold_end@26, clear@28 с одним отброшенным импульсом.
- Сквозной GUI-тест (CUDA, настоящий worker, аудиоустройство ALSA с громкостью 0). Ручное удержание с перетаскиванием при Fly OFF, импульс, bypass блока 7, удержание со снятием через потерю фокуса, Clear. 7 событий журнала в JSON сессии совпали с подтверждениями worker'а, удержания длились 28 и 15 кадров, причины `release` и `focus lost`.

Не проверено: Windows (в проекте и исходном архиве нет `.bat`, запуск проверен через `scripts/start.sh`), реальная мышь и прослушивание на слух, многочасовая работа, отдельный процесс генерации.

## Sync with audio (2026-10-18)

- `tests/test_playback_sync.py` проверяет синхронизатор на поддельных аудиочасах:
  - состояние показывается в момент начала своего звука;
  - из созревших показывается только последнее, порядок восстанавливается по звуку;
  - буфер ограничен;
  - без аудиоустройства или с выключенной синхронизацией состояние показывается сразу;
  - после Stop недозвучавшее отбрасывается, при остановке устройства показ ждёт.
- Сквозной GUI-тест на CUDA с аудиоустройством ALSA (громкость 0, PortAudio сообщает задержку 40 ms): 151 состояние мозга показано через 0 ms (медиана) и максимум через 20 ms после начала своего звука. Генерация при этом шла впереди на 0.44 s (медиана). Ни одно состояние не показано раньше своего звука.
- Не проверено: фактическая акустическая задержка устройства (измерение микрофоном) и восприятие на слух.

## Происхождение заимствованных компонентов

LiquidAion Neural Observatory, commit `dd0f48b408824120cc341c4a56e37227b2091c35`.
`anatomy.py`, `brain_view.py`, `reservoir.py` и исходные данные перенесены из репозитория; `coupling.py`, `engine.py`, `worker.py`, `audio.py`, `gui.py`, CLI и проверки написаны для музыкального приложения. Новая композиция GUI сохраняет анатомический компонент и основу Observatory, удаляя языковую генерацию.

Рекуррентная матрица в первой версии не обучается. Переменные gain/leak/input_strength меняют вычислительную динамику без сброса состояния, но не являются дофаминовой пластичностью. Музыкальный эффект, увиденный в этих проверках, ещё не доказывает уникальности музыкального почерка FlyWire относительно контрольных сетей.
